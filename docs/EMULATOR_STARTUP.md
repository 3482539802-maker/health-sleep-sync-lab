# 自动启动研究模拟器

生成计划仍完全离线。执行、按需读取原数据和批量预检需要连接模拟器时，程序检查已配置的研究实例：关闭则启动一次，正在启动则等待，已启动则继续使用。不会重启已运行实例，也不会改选其他模拟器或实体手机。

等待默认最多180秒，同时检查指定ADB目标和Android启动完成。面板显示启动、等待及保护建立的进度；超时、未授权、名称或目标不匹配会在健康写入前停止。没有started的连接失败任务可以保留原计划继续核验，无需重新抽样或再次删除手机睡眠。

## 开机保护

仅靠运行时UID防火墙不能保护模拟器重新开机；规则会随重启消失。模拟器自身的网络开关也不能作为可靠的离线证据。

自动启动使用受管理实例的应用停用状态：退出任务时先停止健康应用、核验IPv4和IPv6的UID隔离，再执行该实例的`pm disable-user`并保存启动许可。应用和数据保留，停用状态随实例数据保存。下次开机健康应用保持停用；程序核对CPU、型号、版本及Root，重新建立UID隔离后才启用应用，恢复已安装的Frida服务，再通过原有双进程guard建立受控会话。

启用应用前删除旧启动许可；若中途崩溃，就不会凭旧许可直接重启。正常或受控失败退出重新停用并记录。停用或隔离核验失败会保留锁，必须检查私有诊断，不删除锁或启动许可绕过。手动修改应用启用状态、替换实例、升级或重装应用后需要重新配置；启动后的状态不符也会停止。

此设置管理的是电脑研究实例里的健康应用，日常操作通过面板连接。它不改变手机应用或手表配对。研究实例在任务结束后仍可保持模拟器窗口打开，健康应用由程序在连接时启用。

## 首次配置

需要已经打开并核实的研究实例。执行一次以下设置，替换示例参数；命令只设置启动保护，不上传或删除健康记录：

```console
python -m sleep_sync_lab.emulator_startup --config /private/config.json --console /emulator/ldconsole.exe --index 0 --name ResearchLab --state-dir /private/emulator-startup
```

命令核验连接和原版环境，记录现有服务程序SHA-256，停用并保存应用开机隔离。本机启动设置按ADB目标保存在用户目录的`.health_sleep_sync_lab/emulator_startup_private.json`，运行证据保存在指定的仓库外目录。不要提交这些文件。没有配置的环境仍显示明确连接提示；不会猜测安装位置或启动其他实例。

运行时设置独立于不可变健康计划，因此旧计划也可使用新启动功能，日期、随机结果、原备份和started均不修改。私有配置也可显式提供`emulator_startup`对象；设置`enabled: false`关闭自动启动管理。实例序号、名称、控制程序路径、私有记录目录及等待时间必须对应已核实的ADB目标。

服务程序只启动既有且校验一致的`/data/local/tmp/gt2-frida-server`，不下载或安装替代程序。启动命令超时后只查询是否已运行，不重复启动。健康上传或删除仍无自动重试。
