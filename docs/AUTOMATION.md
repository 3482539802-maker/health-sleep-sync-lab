# 脚本面板与自动化

当前睡眠必须先在手机原版删除所选晚并完成同步，程序确认云分段和汇总为空后才重建。电脑和云端单独删除不能确保清掉手机旧源。详见[延迟变化与删除队列](SLEEP_RECURRENCE.md)。

## 使用

Windows安装带Tk的Python并安装requirements.txt后，双击run_panel.cmd，或运行：

```console
python -m sleep_sync_lab.panel --config /private/config.json --runs /private/runs
```

配置参考examples/config.template.json。需要已登录原版17.0.8.310的独立电脑安卓模拟器、电脑模拟器Root和Frida server；不在手机安装／注入，不修改系统时间。真实配置、记录、计划和结果全部放仓库外。

三环与步数字段留空表示不改。整数为固定值，“最小值-最大值”为区间随机整数。活动小时可填写优先新增的整点小时，其他新增小时从允许时段选择。已有活动小时不主动改成未活动。

睡眠日期按起床日选择。整体提前保留原阶段顺序；提前分钟支持单值或随机区间。随机模式同时满足入睡窗口、醒来窗口和总时长；23:00–01:00表示前一日23点到起床日1点。总时长4–12小时，生成浅睡、深睡、REM连续一分钟分段，深睡倾向前段、REM倾向后段。新请求natural_v2允许少量3–9分钟区段，减少超过50分钟连续块。这是合成编辑序列。混合来源、一个查询窗内多晚或午睡自动替换暂不支持；新版随机模式可接受连续原备份含清醒，整体提前仍有原阶段限制。

生成后查看计划日期、目标、睡眠起止、阶段分钟与电脑旧睡眠清理范围。随机结果固定，执行不重新抽取。包含睡眠时，保存计划后在手机原版删除所选晚、完成同步，再勾选已完成手机清理确认并执行。每批上传读回核验；结果显示请求值与实际云端值，未采用不报告成功。

## 面板逐步操作

1. 双击启动入口，确认私有配置与日期。睡眠日期是醒来的那一天，跨午夜不用手动改成前一天。
2. 若只改睡眠，将三环与步数四个目标留空，进入“睡眠”页，勾选“调整所选日期的整晚睡眠”。未勾选时，睡眠输入框中的默认数字不会生效。
3. 选“整体提前”并填120，表示所有分段提前两小时。例如人工示例01:30–09:00会变为前一天23:30–当天07:00，仍是450分钟，原阶段顺序和各阶段分钟不变。填60-120表示随机提前60至120分钟。
4. 或选随机模式：入睡23:00-01:00、醒来07:00-09:00、总时长420-540。程序只选择三个条件同时满足的组合，再生成每分钟的浅睡／深睡／REM序列，前半段偏深睡、后半段偏REM；区间互相矛盾时停止，不写入。
5. 保留原评分是复制备份值，不是根据新阶段算分；未勾选则提交0，原版可能显示未评分。每个日计划只处理所选一晚；默认批量由独立日计划组成。无原睡眠或不支持的午睡／多来源情况停止。
6. 点“生成计划”后核对预览中的实际日期、起止、总分钟、各阶段分钟及清理范围。改了输入框之后必须重新生成；“执行当前计划”使用保存的计划，不会按当前输入框重新随机。
7. 包含睡眠时，先在手机原版仅删除所选晚并完成同步，再勾选确认。程序核验云分段及汇总为空、运动基线一致，清电脑旧数据及已完成的待删除队列；队列及旧时间字典仍有残留便停止。随后每批最多200分钟重建并核验、提交睡眠汇总，再核验完整旧／新查询窗。
8. 执行结果中的云核验通过后，在手机原版正常同步并检查，后续手表同步再验收。不要看到旧记录就立即重复执行已有started的计划。

三环／步数输入的是最终总数，例如热量400-500、锻炼40-50、步数10000-15000，留空不改。活动小时填写目标总数；“优先新增活动小时”填整点小时如20，表示20:00–21:00。允许分配时段限制运动修改，不限制睡眠。各项可以一起生成，但第一次排查某项时分别操作更容易定位派生影响。

## 无界面命令

复制examples/request.template.json到私有目录编辑；模板为人工示例，删除sleep项即不改睡眠。

```console
python -m sleep_sync_lab.automation prepare --config /private/config.json --request /private/request.json --job /private/jobs/new-job
python -m sleep_sync_lab.automation review --plan /private/jobs/new-job/plan_private.json
python -m sleep_sync_lab.automation apply --plan /private/jobs/new-job/plan_private.json
```

睡眠执行需显式加--allow-sleep-delete和--phone-night-deleted，仅在手机已删除所选晚并正常同步后使用。前两步只备份／生成计划，不修改健康记录。新日期创建新任务目录，不覆盖旧计划或删started标记重复执行。

## 方法与证据边界

| 项目 | 方法 | 证据及限制 |
| --- | --- | --- |
| 热量 | 限定时段重分配采用明细，保留备份日汇总残差，同步日总数 | 既有明细进入手机已验收；降低日总数可能忽略，逐柱取整仍可与总数不同 |
| 步数 | 指定时段分配目标，默认优先已有活动小时，同步总数 | 既有修改已获手机反馈；仍可能触发其他派生统计 |
| 锻炼 | 增加未占用分钟的强度记录，同步日总数；降低只尝试总数 | 面板新增流程已实现及模拟测试，尚未单独通过手机验收；已观察降低不采用 |
| 活动小时 | 上传ACTIVE_HOUR/isActive=1及日总数 | 通用适配器新增一个指定小时与日总数已云读回，手机待验收 |
| 睡眠 | 保存完整计划，手机删除所选晚并同步，云空核验、电脑旧源／待删除队列清理，分批重建 | 原电脑／云自动删除路径曾延迟变化；当前流程单独核验，短期云结果不代替手机和手表长期验收 |

历史电脑／云自动删除流程曾当次核验通过、随后发生延迟变化，已停用该执行方式。当前使用手机先清源、程序验证云空并清理电脑旧源的流程，仍需后续正常手机／手表同步验收。不要为了复现成功再删正确记录。原评分可保留备份值，不能称重新计算；不保留时提交评分0，等待原版处理或显示未评分。

日统计较大值优先，随机目标低于已有值可能不采用。运动目前不批量删旧记录，不用isForce假装强制覆盖。睡眠会真实删除重建，不保证recordId、版本或所有派生统计恢复。

启动先验证电脑环境，断开电脑应用网络，加载主进程／后台guard并拦截新增进程后联网，只放行任务请求。退出先停电脑原版，安装并核验UID隔离，再撤guard、自建forward和临时规则；保留当前模拟器运行期间的IPv4/IPv6隔离。guard不是华为限制，也不装手机；不承诺覆盖任意未知写入路径。

## 失败恢复

任务保存backup_private.json、plan_private.json、review_private.json、写入started标记、响应与读回。失败不自动重试；全局锁防并发，已有apply_started任务不能再执行。强制杀进程可能残留锁或规则，先检查，不盲目删锁重跑。睡眠中断可能暂时为空或仅重建部分；备份保留，但恢复需新计划，不保证原服务器身份。

## 操作记录与溯源

新版在私有任务目录追加events_private.jsonl，每行包含带时区时间、进程号和事件。记录备份完成、基线核验、各批提交开始、接口返回、读回通过、任务完成／失败和任务锁释放。接口返回成功与读回通过分别记录，不能把前者当数据采用证明。每个JSON证据文件落盘后记录SHA-256；日志及时flush／fsync。记录本身无法落盘时停止，避免无记录写入。它们是本地排查证据，不是防篡改审计或永久云端日志。

prepare_runtime_private.json、apply_runtime_private.json保存运行时间、Python／系统版本、Git提交和实际Python／JS源码文件哈希；即使代码未提交，也能区分具体运行源码。重复写入前连接失败使用新的runtime和failure文件，不覆盖旧文件。ADB失败时，命令参数、返回码、stdout／stderr及异常链只保存在私有failure文件，不展示在公开面板提示中。原始诊断可能包含设备信息，不外传或提交。

| 文件 | 用途 |
| --- | --- |
| request／config／plan／review | 输入、配置、固定种子与实际修改计划 |
| backup／before_apply | 生成计划及执行前的基线 |
| events、runtime | 操作先后、时间和所运行源码 |
| *_started、*_response、*_readback | 各批可能已写入、接口响应与云采用证据 |
| final、result | 最后读回及目标是否采用；手机仍待验收 |
| *_failure | 出错堆栈及私有原始诊断 |

点击“打开备份目录”即可找到当前任务。排查时保留整个目录，在手机核验后另记同步时间与显示结果；不要删started标记来重试。旧任务仅保留当时已有证据，新版不会伪造旧操作的逐步时间线。

验证命令：python -m unittest discover -s tests -v，以及node --check sleep_sync_lab/automation_native.js。测试仅用人工数据，覆盖随机范围、固定计划、跨午夜、阶段合计、热量残差、失败与禁止重试、删除重建读回。模拟测试不代替手机验收，不证明永久不回流或不可检测。


## 自然睡眠与默认批量更新

新请求使用natural_v2，旧V1和legacy随机计划继续按原算法校验。新增私有可配置钟形预设、三环只增、默认步数不改、旧／新睡眠排除和日期区间批量清单；全日写前核验、逐日哈希及started、失败停止。68项人工测试通过。批量真实云写与手机验收仍待执行，不将人工批量和单日只读生成当真实批量通过。详见[NATURAL_SLEEP_AND_BATCH](NATURAL_SLEEP_AND_BATCH.md)。
