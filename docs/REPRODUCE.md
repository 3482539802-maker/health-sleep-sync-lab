# 完整复现指南

环境先按 [SETUP](SETUP.md)搭建，沿用 $labRoot、$py、$config。所有真实配置、备份、计划和日志在仓库外。每个人用自己的账号、来源和日期，仓库不提供作者的记录或登录环境。

## 选择流程

| 目标 | 流程 |
| --- | --- |
| 空白日期新增三环／步数／睡眠 | 正常面板，不要求原模板或删除 |
| 已有一晚，生成新阶段或整体提前 | 面板先备份，手机删所选晚并同步后执行 |
| 回流后恢复原来那套正确阶段／评分 | 固定快照恢复，新任务，不重跑旧任务 |
| 修改“记录到运动健康的时间” | 尚无已验证云方法，不提供手机该栏修改选项 |

## 面板正常新增与替换

1. 启动面板并填自己的起床日。手机原版为验收位置，系统时间正常。
2. **只改睡眠**用自定义，四个运动目标全部留空，活动时段可空，勾选睡眠。默认方案会控制多个项目，不能把它当睡眠 only。
3. 随机模式填自己的入睡／醒来／总时长范围，选择“按新分段估算”可得到脚本分数，上限 95、不保证每晚达到上限。整体提前保留原阶段，需要原分段；恢复原评分需要有效备份。见[评分规则](SLEEP_SCORE.md)。
4. 生成并审阅固定计划。整体提前、保留原分以及替换已有睡眠才需“读取原数据（按需）”，保存完整备份和范围。执行不重新抽样；改输入需重新生成，更新代码后重开面板。
5. 所选晚无原睡眠且电脑无旧源可直接执行，不删空记录。有旧睡眠时，**先保存计划和备份**，手机“睡眠 → 所有数据 → 删除选择”只选这一晚，核对日期／来源／选择数量后删除并正常同步，无需 USB。
6. 已有睡眠删除后勾选确认执行。程序核验云分段／汇总均空、原运动基线一致，清电脑旧分段、已完成删除队列及旧起止字典，读回空后上传。睡眠来源为已登记穿戴设备，类别来自原版字典；云查询 source1 不直接用于请求，汇总请求为 source2／deviceCode0。
7. 每批最多 200 分钟并读回，最后检查完整旧／新窗、来源和汇总。手机正常同步检查日图、所有数据、来源和评分。云正确而手机详情空白先查来源／类别，不能整套重复上传。

正确后保存**正确的完整云快照**。面板任务 final_private.json 通常可用，也可通过 sleep_repair snapshot 保存六域快照；先核对日期、全部阶段和汇总，文件叫 final 不等于正确。固定恢复要求连续浅／深／REM分钟、唯一穿戴来源、类别及完整起止／阶段时长／评分。

## 从正确快照恢复固定睡眠

这对应“恢复此前同一套正确阶段／评分，运动不动”。先暂时关闭手表，手机正常网络同步仍可用；关表不会清除手机已有缓存文件，也不能单独证明旧数据上传端。

### A. 准备新独立任务

用自己的此前手机验收正确的六域快照，不用回流混合数据生成，不复用旧 apply。

```powershell
$target = Read-Host '输入自己此前正确的 snapshot_private.json 或 final_private.json 路径'
$job = Join-Path $labRoot ('repairs/' + (Get-Date -Format 'yyyyMMdd_HHmmss'))
& $py -m sleep_sync_lab.sleep_repair prepare --config $config --target-snapshot $target --score-origin estimate --job $job
$plan = Join-Path $job 'plan_private.json'
& $py -m sleep_sync_lab.sleep_repair review --plan $plan
```

estimate 表示备份分数为脚本估算，原评分用 original，无法确认用 unknown。复制备份的分数和完整 professionalSleep，不重新算分，不改阶段。

prepare只读，保存当前六域、前后邻日、电脑源／队列和四表计数，核验登记来源，固定目标、清理范围和哈希。核对 review 的自己的日期／起止／时长／评分来源／睡眠 only／电脑清理范围。跨多晚、下午睡眠、含清醒／未知阶段、缺汇总、来源不属本账号等情况停止，不改字段绕过检查。

### B. 手机只删所选晚并同步

在备份与 plan 保存后，手机原版仅删这一晚，正常同步并确认，手表继续关机。不要清应用数据、改账号、配对或删其他日。

### C. 核验清源后重建

```powershell
& $py -m sleep_sync_lab.sleep_repair apply --plan $plan --phone-night-deleted --watch-powered-off
```

旗标记录自己已经实际完成的动作，不能只为通过检查添加。工具两次确认云分段与汇总都空、完整运动和邻日基线一致、来源／类别及目标通过后才写。

如果私有证据显示电脑所选范围仍有旧分段／已完成删除队列，核对 pc_cleanup_scope 只覆盖这一晚后，显式加 --allow-pc-cleanup。使用现有单晚本地删除与已完成任务退休，不再删云；核心、统计、字典和队列须读回清空。**只有没有 apply_started 的写前失败计划可再尝试。** 清理或上传已开始则保留证据评估实际状态，不再次 apply。

sync_cache 非空、范围外有旧源或清理后统计残留时停止，不擅自删未知缓存／统计。不要删库、标记或自动扩大范围。

分批上传后核对完整窗的实际时间／阶段／来源，然后仅一次提交正确汇总，两次读回完整 professionalSleep、运动和邻日。失败不自动重试，保留 apply_started 和各批 request／started／response／readback／failure；接口报错也可能已部分采用。

### D. 手机和延迟验收

手机正常同步，重新进入日图及所有数据详情，核对起止／总时长／各阶段／来源／评分及旧尾段消失。截图／数字仅存私有目录。退出写会话后独立查询；手机同步后再查可判定是否立即回流：

```powershell
& $py -m sleep_sync_lab.sleep_repair verify --plan $plan
```

verify只读，可保存多份快照，不上传。核对实际内容，recordId 仍在不能证明内容不变。开表、独立手表同步和较长时间后的结果分别记录；目前方法只验证过关表条件的一次手机正常同步及短期云读回，不保证永久稳定。

## 证据等级与未解决项

| 结果 | 结论 |
| --- | --- |
| 请求成功 | 调用成功，仍需读实际采用值 |
| 分段完整窗正确 | 此时云时间／阶段／来源正确 |
| 汇总完整匹配 | 此时云起止／阶段时长／类别／备份分数正确 |
| 手机正常同步正确 | 此次手机原版采用目标 |
| 退出后独立查询正确 | 这段短期内未观察到回流 |
| 开表后长期正确 | 需要另行实际验证，目前不能承诺 |

已观察电脑旧分段／删除队列残留；静态分析定位穿戴文件被手机重解析、逐分钟插入原阶段的独立路径。具体上传端需现场日志，不凭版本号或电脑旧段断言。记录时间的电脑本地实验与云改不同，当前纯内存转换探测未得到可用云端指定方式。

公开固定恢复工具是已验收私有方法的参数化版本。新通用代码用人工数据验证云未空、汇总／来源、运动／邻日变化、范围外旧源、缓存、阶段覆盖／旧尾段和失败防重复，没有再次写真实健康数据演示。其他问题见[TROUBLESHOOTING](TROUBLESHOOTING.md)。先从一个明确日期开始；真实批量及长期同步仍未完整验收。
