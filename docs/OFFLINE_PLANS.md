# 按需读取原数据与空白日期新增

新方案的生成和执行支持所选日期完全没有原健康数据：无运动明细、锻炼分钟、活动小时、步数、睡眠分段和日汇总，都可以按目标构造新的明细与日汇总。生成只使用输入、日期、时区和私有预设，不启动ADB、模拟器或Frida。

默认方案不再强制经过“执行前备份/核验”。点击“生成计划”查看结果，再点击“执行当前计划”。原数据读取入口改为“读取原数据（按需）”。默认不保留原评分；整体提前睡眠、明确保留原评分或显式use_original设置才需要先读取对应原数据。已有睡眠替换也需要先保存备份。

| 项目 | 原数据存在 | 原数据缺失 |
| --- | --- | --- |
| 默认三环 | 对存在的日汇总字段比较，不高于原值则保留 | 跳过比较，生成明细和汇总 |
| 默认步数 | 保留原步数 | 按生成热量配套生成步数；这是合成规则，不是测量或热量换算公式 |
| 自定义三环／步数 | 保留未选字段及允许时段外的内容，必要时新增分钟 | 从零构造选中目标，留空字段继续不改 |
| 随机睡眠 | 替换前保存备份，手机仅清理所选晚并同步 | 直接生成起止、阶段及汇总，不要求删除空记录 |
| 整体提前 | 读取原起止和阶段，固定提前分钟数 | 提示缺少所需原睡眠，不编造原阶段 |
| 保留原评分 | 读取删除前评分备份 | 提示缺少评分；可取消该选项生成随机睡眠 |

执行连接已登录的电脑原版，自动读取当前状态，用于可选比较、保留其他字段及发现睡眠冲突。查询成功并返回空数据是正常输入；查询失败不能当成空数据。这项执行核验不要求用户提供原健康记录或先点击读取按钮。

上传来源从原版已登记的当前账号客户端取得，不从某条历史健康记录复制。运动优先使用已登记的手机来源；运动来源不唯一时，可在私有配置指定upload_device_code，必须属于当前账号已登记的原版来源。新合成睡眠单独使用已登记的穿戴设备来源，并从原版字典填写汇总设备类别；缺少唯一来源时在任何健康写入前停止，多个来源可指定sleep_upload_device_code。已有具体原来源的整体提前仍保留原来源。代码不伪造设备ID、不创建新登记，也不改变配对。完全没有健康记录与尚未登录／没有登记来源是两种状态。

自定义四个运动目标留空表示不改；允许分配的时段留空表示不限时段，不会因此要求修改运动。只启用随机睡眠、其余全部留空可以离线生成。不填写任何目标且未勾选睡眠仍提示至少选择一个修改项目。

运动分配排除旧睡眠及新睡眠，活动小时按清醒整点选择，运动和锻炼分钟落在所选活动小时及允许时段内。新步数分钟限制在每分钟240步以内；热量明细及汇总均使用毫千卡。超过清醒容量的目标会停止；默认活动小时容量不足时明确调整或跳过，不因此下调已有更高原值。随机起止和阶段在生成时固定，执行不重抽；实际跳过项目及分配保存在resolved_plan_private.json和resolved_review_private.json。合成数据不代表实际监测。

## 已有睡眠与批量

所选晚已有云睡眠或电脑旧源时，直接执行在任何运动上传之前停止。先点击“读取原数据（按需）”保存备份和完整范围，再在手机原版仅删除所选晚并正常同步，勾选确认后执行。核验云分段及汇总空，限定清理电脑旧段、删除队列和旧起止字段后才重建。空白日期不要求勾选，也不调用本地／云端删除接口。

批量支持所有日期为空。第一天写入前，所有日期都完成只读冲突、容量及来源核验；后续某天已有睡眠、读取失败或无法合理分配，会阻止开始写入。执行中失败停止后续日期，成功日期不自动回滚。旧计划和全部started保留。

## CLI与兼容

```console
python -m sleep_sync_lab.automation prepare --config /private/config.json --request /private/request.json --job /private/jobs/new-job
python -m sleep_sync_lab.automation review --plan /private/jobs/new-job/plan_private.json
python -m sleep_sync_lab.automation apply --plan /private/jobs/new-job/plan_private.json
```

直接执行适用于无原数据依赖且无睡眠冲突的新方案。需要原数据时运行bind并核对返回的plan_path。替换旧睡眠额外需要--allow-sleep-delete和--phone-night-deleted；批量使用sleep_sync_lab.batch，确认参数为--phone-nights-deleted。

新任务默认planning_mode=standalone。版本5为直接可执行方案，版本6为按需绑定方案；版本3表示需要读取原数据，版本4旧绑定及版本2旧完整计划按原算法校验。显式planning_mode=legacy用于旧流程兼容。同一来源的直接执行／绑定共享started约束，不能重新绑定绕过已执行标记。

测试覆盖人工空白日期的生成、五项明细及汇总上传读回、按需比较、缺少来源／读取失败、已有睡眠、原评分／阶段保留、批量预检及防重复。当前 155 项 Python 测试通过，实际留空字段仅睡眠界面生成和当前账号设备来源只读核对通过。旧版新增曾有云正确但手机日详情空白、所有数据来源为手动输入的反馈；限定单晚的穿戴来源及类别替换已通过云读回和手机睡眠图、起止、阶段、来源验收。此次未重做运动，真实全空组合任务、其他日期与后续手表同步稳定性仍另验收。
