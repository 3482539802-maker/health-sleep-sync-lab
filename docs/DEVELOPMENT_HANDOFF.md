# 脚本优化与功能开发交接

最新睡眠流程优先读[SLEEP_RECURRENCE](SLEEP_RECURRENCE.md)：原自动清电脑／删云后立即重建已有延迟删除和旧源合并问题。当前必须手机先删所选晚并同步，核验云分段／汇总均为空，限定清理电脑旧段、统计待删除项和旧时间字典后重建。主进程／后台均guard、新进程暂停、退出保留当前模拟器运行期的UID隔离。旧流程段落是历史，不能据此再运行自动删云立即重建。诊断启动曾引发非预期后台删除，必须保留该事实。

## 目标与当前状态

维护一个可直接运行的中文桌面面板和CLI，让用户在手机系统时间正常、现有原版运动健康入口不变的条件下调整三环、每日步数与单晚睡眠。用户接受新增数据及睡眠删除重建方案，下一阶段准备优化脚本和添加功能；具体新需求由用户提出，不将候选改进当已授权真实实验。

单晚睡眠已实际重建及云读回，但原自动删云流程随后暴露延迟删除与旧源合并缺口。当前手机先删所选晚、云空核验、清电脑旧源及删除队列再重建；新的独立恢复任务已逐批及延迟云核验。手机／手表同步后持续稳定性仍待独立反馈，不宣称所有手机／日期通用成功。诊断启动曾触发非预期后台删除，其证据必须保留。

真实材料只在私有工作区，此公开交接不含个人数据。使用已登录原版17.0.8.310的独立电脑安卓模拟器、电脑模拟器Root、ADB和Frida；手机不注入、不改系统时间。升级应用后需重新核对内部类与签名。

## 必须保留的行为

prepare读取备份和生成固定计划，不写健康；review校验预览；apply才执行。随机值在生成时固定，编辑面板后需重新生成。执行前重新核验所选域基线和计划文件哈希；睡眠有明确单晚确认。上传每批读回，接口返回0不等于采用；日总数下调可能忽略。

三环／步数留空不改，单值为最终目标，区间随机整数。运动限定允许时段，步数／锻炼默认优先已有活动小时；活动小时新增未活动整点，不能保证其他派生统计无变化。睡眠整体提前保持原阶段／时长；随机模式满足入睡、醒来与总时长窗口，浅／深／REM为合成分段。保留原评分只复制备份；未选则提交0，不计算新分数。

睡眠顺序：保存完整计划和备份→用户在手机原版仅删除所选晚并正常同步→确认所选窗云分段和汇总为空、运动基线一致→清电脑旧源→再次云空核验→限定事务清已完成删除队列与旧起止字典→读回确认无旧源／待删除→每批最多200分钟重建读回→汇总及完整旧／新窗核验。不能只读目标区间来判断旧尾段消失，不能用本地删除函数true替代数据库读回。

每个新任务在仓库外独立目录，保存request/config、backup/plan/review、before_apply、各started/response/readback、final/result/failure。events_private.jsonl按时区时间记录各阶段及证据SHA-256；prepare/apply runtime记录Git与实际Python／JS哈希。原始ADB输出和异常链只进私有失败文件。日志落盘失败应停止，不能继续无记录写入；本地日志不承诺防篡改或取代服务器审计。

健康写入不自动重试，已有apply_started不重跑。Root只读id探测最多3次；后台就绪检查和只读查询有界限。启动使用解析Launcher后am start，不用monkey。源码更新会阻止旧面板启动新操作，需要关闭重开；任务进行中不强杀。guard是本项目电脑隔离手段，不是云端权限屏障，不应绕过它上传旧记录。

## 下一轮开发建议

先根据用户具体需求确定变更，再用人工fixture实现及验证；无需真实账号即可做界面、参数校验、日志和算法开发。候选方向包括更清楚的计划差异预览、私有手机验收反馈记录、失败后只读诊断、配置预设、日志检索以及评分行为说明。多日操作、恢复中断任务或扩大删除范围需要专门设计，不能简单循环旧apply或删除started。

输入预检和启动／回调／异步失败现在保存私有记录，面板显示具体字段或ADB步骤及状态码。生成后编辑输入会阻止误执行旧计划；默认方案锁定预设控制字段。详细规则见[面板诊断](DIAGNOSTICS.md)。当前仍可优化：组合任务中睡眠失败时运动可能已提交；无原睡眠／午睡／混合来源不自动替换。随机替换可接受连续备份里的清醒，但不合成清醒；整体提前仍有原阶段限制。自定义下调可能不采用，默认方案遇到不高于原值则跳过。批量并非事务，不能删marker重试。

变更前检查git status及现有任务锁，保留用户改动和全部历史证据。测试覆盖真实故障与边界，不让测试简单镜像实现。JS变更检查语法，必要时只读核对当前适配版本；没有明确日期、备份与授权，不为测试执行真实删除／上传。提交使用显式文件白名单和项目noreply署名，公开资料再做隐私检查。


## 自然睡眠与默认批量更新

新请求使用natural_v2，允许少量3–9分钟阶段，降低超过50分钟连续块的频率，保持底层V1各阶段总分钟和总时长。V1及legacy旧计划仍用原生成器。新增私有加权预设、三环只增、步数默认不改、旧／新睡眠排除和独立逐日批量清单；全日写前核验、逐日哈希及started、失败停止。批量睡眠须先手机清理所选各晚。85项人工测试通过。多日真实写入与持续手机验收仍待验证。详见[NATURAL_SLEEP_AND_BATCH](NATURAL_SLEEP_AND_BATCH.md)。
