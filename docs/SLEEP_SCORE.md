# 睡眠评分与显示检查

睡眠分段、来源／类别、睡眠汇总和评分分别核验。上传分段成功不会自动产生评分，也不能替代手机日详情验收。

## 面板评分模式

| 选项 | 行为 | 是否需要原数据 |
| --- | --- | --- |
| 不提交评分 | 提交0，手机通常显示`--` | 随机模式不需要 |
| 恢复备份原评分 | 复制删除前备份中1–100的有效评分，不重算 | 需要原评分备份 |
| 按新分段估算 | 按目标分段计算项目定义的指标，明确标记非华为官方评分 | 随机模式不需要 |

整体提前始终需要原分段。默认仍不提交评分；需要估算时在睡眠页明确选择。新估算不会改变已生成的起止、阶段和随机运动目标，不增加健康写入次数；分数随日汇总提交。

计划／预览／执行结果包含分数和来源。估算还保存算法版本、各项贡献和限制。原版手机的数值字段无法附带“估算”标签，也可能根据这个数值显示星级、超过其他用户的比例及建议；这些界面文案不验证算法正确性。

## 新估算模型与旧计划兼容

新生成的估算请求使用`stage_estimate_v2`，按下面的同一套规则计算原始分数，再将提交分数限制为1–95。计划保存`raw_score`、`score_ceiling=95`及模型版本，预览和结果中的分数是实际提交值。原始分数达到或超过上限时提交95；低于上限时按计算值提交，不保证每晚都在90分以上。

已生成的V1计划保持原值。缺少`score_model`的旧估算请求仍按`stage_estimate_v1`计算，范围1–100，不修改旧计划或防重复标记。原评分恢复也不受估算上限影响，仍要求有效的1–100原分。

关闭旧面板后重新打开才会加载新版；修改评分选项后需要重新生成计划。已有started的任务不能靠重新生成或删除标记再次执行。

## 两个模型共用的公开规则

仅支持240–720分钟连续浅睡／深睡／REM序列。权重是项目的可审查选择，没有临床验证，不复刻厂商算法：

- 时长45分：420–540分钟满分；向外偏离每180分钟扣完该项。
- 深睡比例20分：15%–30%满分；向外偏离每15个百分点扣完该项。
- REM比例20分：20%–30%满分；向外偏离每20个百分点扣完该项。
- 阶段切换15分：每小时不超过6次满分；超过部分每12次扣完该项。

每项最低0，总和四舍五入后得到原始分，再按所选模型上限限制。V1的范围为1–100，V2的范围为1–95。同一序列重复计算结果相同，不读取原分数、不随机抽分。达到上限只说明该简化规则符合项目设定，不能解释成测得完美睡眠。没有传感器质量、呼吸、入睡潜伏期或实测睡眠效率等信息。睡眠不足、阶段失衡或高频切换会降低结果；清醒及未知阶段停止估算。

原版静态分析发现设备二进制同步数据的计算入口，日统计路径读取已有评分。目前没有验证从本工具分段调用厂商重评分的安全方法，因此不提供假“官方重算”选项，也不调用可能重写统计的未知入口。

## 避免云端有睡眠而手机详情空白

新随机睡眠必须使用当前账号唯一的已登记穿戴来源及原版设备字典类别。运动来源独立选择；睡眠不退回手机来源。缺少来源或有多个来源时，在第一次健康写入之前停止；可在私有配置明确指定登记的`sleep_upload_device_code`。

单日及批量均在任何运动／睡眠写入前检查：目标来源、汇总类别、日期／时区、上传请求`dataSource=2`、汇总起止与各阶段分钟、有效评分。云查询可能返回`dataSource=1`，查询对象不能原样用作上传请求。

旧计划若使用手机来源、缺类别或类别不匹配，保留原文件和标记并提前停止。未开始的任务用新版重新生成、审阅；已有started的任务不重跑。修复已上传睡眠须单独备份并取得具体范围授权。

结束时核验完整睡眠窗、分段、来源、类别、汇总和评分。结果仍标手机待验收：正常同步后核对日详情起止、阶段、所有数据的设备来源及评分。短期手机通过不能保证以后设备同步永不回流。
