# 研究结论与证据等级

新增运动与同步结论：

- 原版可以后台自动尝试上传，无需手动下拉。诊断guard是电脑实验脚本，阻止旧记录无意重传，不是厂商权限限制。
- 原版逐段合并不会因云端少了某些分段就完整替换本地；重新合并改变采用状态时可能重新待上传。旧尾段回流已观察，但某次确切上传端缺历史日志。
- 活动小时步数判定为单条至少40步或一小时累计至少100步；热量也有独立阈值。改步数可能增加活动小时，不能只看步数日总数。
- 字典ACTIVE_HOUR/isActive=1上传与日活动小时汇总增加，已由新自动化适配器定向云读回；手机验证另行记录。
- 本地日热量／活动小时合并有较大值优先；云端降低请求返回成功但未采用的情况已实测。isForce取自PushAction，不能当强制覆盖保证。
- 面板睡眠生成／提前及自动删除重建有人工fixture测试，并已有一次真实单晚电脑／云端删除重建成功、分段和汇总云核验通过。用户反馈脚本可用，未逐项证实手机显示或持续稳定性。参见[AUTOMATION.md](AUTOMATION.md)与[开发交接](DEVELOPMENT_HANDOFF.md)。

| 结论 | 证据与限制 |
| --- | --- |
| 电脑显示Hook不会自动改变手机或云端 | 原版隔离显示实验；与真实记录修改分开 |
| 无Root重签不是现成可交付路线 | 隔离电脑实例多个对照未通过启动；手机签名／特权仍有前置限制 |
| 原版type9上传和查询可用 | 当前版本真实单日实验；不是官方公开写入API承诺 |
| 提前起止可能新增，而非覆盖旧recordId | 当前版本一分钟对照；清理经具体授权 |
| 孤立前段可能使起止标签消失 | 用户手机反馈与多段图表源码分析；连续补段后恢复 |
| 云删尾段不必然删除手机本地尾段 | 云时间和版本查询正确，手机保留旧尾段；已观察响应无该尾段删除项，未证明所有接口均无删除机制 |
| 原版手机整条删除后重建可解决一次旧尾段保留 | 单日三批上传、手机原版日图和数据详情交叉验收；未验证长期自动处理 |
| 分段与睡眠评分是不同数据 | 分段重建后评分缺失；评分对应独立汇总sleepScore和本地stat_type44203 |
| 备份原评分可通过独立汇总恢复 | 原版电脑当日统计保留原评分；保持当前起止及阶段时长，仅恢复原评分，云读回一致，用户正常同步后确认手机评分显示恢复；不是重新计算 |

工具不是医疗分析软件，不解释合成记录的生理真实性。本仓库不分发参与者实测原件；对本机结果的证据可追溯于私有工作区，公开说明仅保留技术结论。
