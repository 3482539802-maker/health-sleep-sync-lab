# 故障处理

电脑原版采用解析入口后`am start -W -n`明确启动，避免随机输入事件启动失败。启动入口、后台未就绪及已知校验错误显示具体中文原因，不显示原始请求或私有异常。写入前连接失败保留原计划及全部失败记录；没有started标记且云备份仍一致时，修复连接后可执行该计划。有写入标记的计划仍禁止重跑。

用`python -m sleep_sync_lab.panel --config /private/config.json --plan /private/job/plan_private.json`可恢复计划显示，打开不会执行。

面板先看私有任务的review、result和failure文件，不重复执行带started标记的任务。实际云端值与随机请求不同，可能是统计合并没有采用下调；不要删除标记重跑。另有电脑会话锁防止两个面板同时连接：进程异常退出后，先检查原版进程、forward和网络规则，再处理残留锁。锁仅是本机任务管理，不是云端权限限制。

| 现象 | 下一步 |
| --- | --- |
| resultCode1004或auth failed | 停止写入；确认原版已登录且正常联网。失败不等于无数据，不打印或复制令牌 |
| 云端正确、手机旧尾段仍在 | 查看日图和所有数据；云缺失项可能不删除本地。整条删除后重建需要具体授权和删除前备份 |
| 起止标签消失 | 检查是否有孤立前段和缺失分钟，不能只补一个很早的分钟就宣称入睡已改变 |
| 评分为“--” | 检查独立汇总和原评分备份；先保住正确分段，原评分恢复另验证 |
| schema、内部方法或应用版本不匹配 | 重新核对适配器，不盲目替换类名后上传 |
| marker已存在 | 不删除marker；读回服务器与进度文件，确定是否已有部分写入 |
| 当日混合多个设备／来源 | 计划器拒绝；不能擅自合并或删除用户其他来源 |
| 手机锁屏 | 用户自己解锁；不采集密码、不绕过锁屏 |
| 同步后原时段重新出现 | 保存限定快照，检查手表重传与来源；长期稳定性尚未保证 |

异常输出应留本机私有目录。对外提问只分享去标识后的方法签名和错误类别，不分享完整请求、响应、截图或设备日志。
