# 给新 AI 的完整操作流程

下一阶段为脚本优化与功能开发，优先阅读[最新开发交接](DEVELOPMENT_HANDOFF.md)。下文编号步骤是旧CLI手机手动单晚删除流程；面板自动流程见[AUTOMATION.md](AUTOMATION.md)，计划格式与授权方式不同，不能混用。

## 新增桌面面板

先读[自动化说明](AUTOMATION.md)。`python -m sleep_sync_lab.panel`提供单日三环、步数和睡眠目标；`python -m sleep_sync_lab.automation`提供prepare/review/apply。新计划支持跨午夜整体提前及随机入睡／醒来、合成阶段，并含原云备份、电脑本地睡眠清理范围、固定随机种子和完整执行标记。

以下旧CLI流程仍是已验收的手机手动删除路径。新面板已实际完成一次电脑／云端单晚删除重建，分段和汇总云核验通过，用户反馈脚本可用；具体手机字段与长期稳定性没有逐项验收，不把两种证据混称。真实活动小时新增与汇总已用新适配器云回读。运动日统计下调可能不采用，实际结果必须查看云读回并由手机验收。

请先读本文件和README，然后检查实际工具版本、环境、目标、备份和已有授权。不要根据示例直接写云端。本流程处理一个日期，不批量改历史。

## 1. 环境与目标

确认用户要求的是现有手机原版入口，而不是电脑预览。目标日期、时区、入睡／醒来及保留的总时长必须明确；需要合成前段时明确标注。手机无需Root或改系统时间。

电脑独立安卓模拟器中运行已登录的原版运动健康。由用户自己登录，不收集密码／验证码。模拟器中的Frida server与Python包版本匹配，app17.0.8.310是当前签名适配依据。物理手机不得作为Frida目标。工具要求模拟器设备名；优先校验ro.kernel.qemu。部分PC模拟器不提供该标志，此时必须先独立确认它确为隔离PC实例，在私有配置设emulator_verified=true并填写其model／board，工具另校验x86 CPU及两项属性完全一致。未知环境停止。

真实配置复制到仓库外，修改config的date、timezone、adb和serial。日期要对应应用的睡眠详情所属日期；跨午夜／午睡目前没有通用验证，不凭日历午夜猜归属。

## 2. 删除前先备份分段与原评分

运行`backup --config CONFIG --out BACKUP`。这是只读：查询指定日type9分段及科学睡眠汇总，保存完整内容在私有目录。检查resultCode、日期、来源、分段重复／连续性及原评分。保留hash和副本，不覆盖既有文件。

先保存当天手机原版日视图与“所有数据”的对照，截图只留私有目录。仅ADB无法取得无Root手机完整私有数据库；云备份不是完整手机备份。

## 3. 生成并审阅目标

运行`plan --backup BACKUP --target-start ISO --target-end ISO --reference-start ISO --out PLAN`。工具保留目标窗口内原分钟；填补缺失分钟时按明确参考起点顺序复制本人原阶段。参考时段不够、混合设备、重复时间、非法阶段或目标不在配置日内时拒绝。

计划中有目标、原始备份、每个合成分钟的来源映射及SHA256。真实修改计划不能发布。它不是生理测量；若用户希望直接整晚平移，可另外构建经校验的目标，不将本工具的补段行为混为平移。

先使用`review --plan PLAN`检查时间／时长、合成数量和原评分是否有备份。把具体删除范围、备份与可能损失向用户说明。删除整条可能同时删除当天云端分段和评分；上传失败可能当日为空或部分数据。内容恢复不保证服务器版本与统计恢复。

## 4. 手机原版删除指定日的整条睡眠

只有明确授权该日期整条删除后才执行。正常路径为“睡眠→菜单→所有数据→删除选择”。只勾选目标日期，共1条，确认来源和类型；不能点全选。若当天有多个来源、确认框范围不清或会删除其他类型／日期，停止并说明。

确认后检查当天条目消失，可见相邻日期数值不变。不要清应用数据、重新登录、改配对或解锁引导程序。工具不提供自动删除功能；AI如用ADB导航，必须先核对UI、实际勾选数和确认框，并由用户自行解锁屏幕。

## 5. 记录授权后限定重建

在私有目录填写grant模板：真实date、已审核PLAN文件SHA256、明确授权allow_rebuild，以及已观察到原版当天删除的确认。旗标只是记录授权，不能代替用户许可。

运行`apply --config CONFIG --plan PLAN --grant GRANT --out RESULT`。工具先重新查询当天云数据；只接受为空或已与完整目标一致，不删除意外记录。目标以最多200条分批上传，每批读回核对预期状态，任何失败立即停止。RESULT.started防重复标记不可删除。工具不调用完整同步服务，也不改手机数据库。

如果部分批次失败，查看私有RESULT.progress.json与快照。不要整夜盲目重跑，不清防重复标记；先确定服务器实际状态，再制定用户可审阅的补全步骤。

## 6. 手机验收

手机首页正常下拉同步，退出并重进目标睡眠“日”视图，核对：日期、入睡、醒来、总时长、图表连续性、旧尾段消失。“所有数据→当天→数据详情”再核对起止和来源。最后只读查询云端，确认没有旧尾段重现。

只在未注入手机显示正确后称此次目标完成。请求返回0、电脑正确或云端条数正确均不足。查看不需电脑长期运行／USB连接；当前写入工具仍依赖电脑。后续每日自动处理、手表重传和全统计一致性另验收。

## 7. 原评分恢复

如果评分为“--”，先查原备份汇总的sleepScore；缺失时只读查原版电脑仍保存的hihealth_stat_day中当日stat_type44203。查询结果留私有目录，必须能追溯为原评分，不编造或提高分数。

原始评分恢复需要单独的用户请求或既有明确授权。填写grant的allow_restore_original_score，运行`restore-score --config CONFIG --plan PLAN --grant GRANT --out RESULT`。工具从计划的删除前备份取得原评分；读取当前正确汇总，仅将sleepScore设回原值，保持当前时长、阶段和起止，按照原版合并汇总格式dataSource2/deviceCode0提交一个日期，保存请求前后副本并读回。

手机正常同步后再次验证评分和时间。这是恢复原评分，不是根据合成分段重新计算新评分。其他派生指标没有完整备份时不得声称全部恢复。若计划没有原评分，需先取得可追溯备份并单独制定恢复方案；不要给工具传任意分数。

## 8. 交付与隐私

记录本次目标、授权、完整备份路径、hash、marker、每批结果、手机验收和未解决项。原件只留用户指定私有位置。公开摘要不写真实日期、睡眠时间、评分、阶段序列、ID、截图或设备序列号；公开代码使用参数化配置和合成测试。

适配器依赖内部类／API，遇到应用升级、认证失败、服务器行为改变或用户目标变化必须重新验证，不承诺不可识别或成功率。
